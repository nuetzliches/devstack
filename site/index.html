devstack

Runs your local development stack: containers from your Compose files, your services built in the background. A change goes live only once it is healthy, and you can always see whether it has.

Install

No admin rights needed. The script shows the download's progress, checks it against the release's checksums, puts devstack on your PATH and lets the dashboard start at logon. A first install opens the dashboard when it is done, and this page notices it by itself. Run it again to update.

Then, in your repository

  1. devstack doctor says what this machine still needs for the stack (Docker, tools, ports).
  2. devstack up starts it; devstack ui opens the dashboard.
  3. devstack skills install gives your coding agent the skills to run and configure it.

No devstack.toml yet? devstack init drafts one from the repository; the stack file reference and the example explain every key.

Your change, live or notEvery service says whether the code you saved is running yet, building, or failed and why.
No broken restartsA new build takes over only when it is healthy; a compiler error leaves the old one running.
Your Compose filesInfrastructure comes from the Compose files you deploy with, plus a small dev overlay.
Agents includedAn MCP server and generated skills let coding agents run, check and fix the stack.
Every worktree a laneEach git worktree runs the whole stack on its own ports with its own containers: many branches, many agents, no collisions.
Lanes on the team's serverdevstack up --on build-server runs a worktree's lane on a machine of your pool, its ports forwarded to yours. Move it, share it, give it the main ports.
